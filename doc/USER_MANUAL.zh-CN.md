## 1. 系统模式选型与拓扑

| 对比维度 | 直连模式 (Direct P2P Mode) | 中央枢纽模式 (Central Hub Mode) |
| :--- | :--- | :--- |
| **架构原理** | Sender 通过内置 ZeroMQ 直接广播，Receiver 建立 TCP 点对点直连。 | 所有 Sender 与 Receiver 统一连接到中心 Rust Hub 服务端，由 Hub 进行透明路由。 |
| **适用场景** | • 单台 PC 或单台云 VPS 本地终端互跟<br>• 1个主账户跟 1~3 个从账户<br>• 追求零额外进程与极简部署 | • 跨 VPS、跨多机房远程云跟单<br>• 几十至上百个多对多账户矩阵<br>• 需要 Web 监控大屏、手机告警与双机热备 HA |
| **依赖环境** | 仅需 MT4/MT5 终端与配套 DLL，**无需运行任何服务端或安装 Python/Rust**。 | 需要在服务器/VPS 后台运行 `copier-hub.exe`（可一键注册为 Windows 服务）。 |
| **延迟表现** | **< 2ms**（本机环回内存级传输） | **< 10ms**（取决于节点到 Hub 的公网网络物理延迟） |

## 2. 5分钟快速上手：直连模式 (Direct Mode)

适合在同一台电脑/VPS 上，将一个主账户（MT4 或 MT5）的订单实时同步到从账户（MT4 或 MT5）。

### 步骤 1：安装文件到 MetaTrader 数据目录
1. 打开喊单端和跟单端 MetaTrader，点击顶部菜单 `文件` -> `打开数据文件夹`。
2. 将发行包中的对应文件复制进去：
   - **MT4 终端**：
     - `CopierSender.ex4` / `CopierReceiver.ex4` -> 放入 `MQL4\Experts\`
     - 32位 `libzmq.dll` -> 放入 `MQL4\Libraries\`
   - **MT5 终端**：
     - `CopierSender.ex5` / `CopierReceiver.ex5` -> 放入 `MQL5\Experts\`
     - 64位 `libzmq.dll` -> 放入 `MQL5\Libraries\`
3. *(提示：也可以直接双击直连包内的 `install_direct.bat`，脚本会自动探测并批量拷贝至本机所有终端)*。

### 步骤 2：开启交易与 DLL 权限（至关重要）
每个终端都必须设置：
- 打开菜单 `工具` -> `选项` -> `智能交易系统`（或 `EA交易`）；
- 勾选 **【允许算法交易 / 自动交易】**；
- 勾选 **【允许 DLL 导入】**；
- 点击确定。

### 步骤 3：加载 EA 开始跟单
1. **在主账户 (Master) 图表上**：
   - 打开任意 1 个图表（例如 EURUSD M1）；
   - 将导航栏中的 `CopierSender` 拖入图表；
   - **所有输入参数保持默认即可**（默认端口自动分配，`HubEndpoint` 留空即为 Direct 模式）；
   - 点击确定。图表右上角出现笑脸或蓝色帽子，图表左侧弹出 HUD 状态面板，记录面板显示的 `Listening on port: 5000`（或类似端口号）。
2. **在从账户 (Slave) 图表上**：
   - 打开任意 1 个图表；
   - 将 `CopierReceiver` 拖入图表；
   - 切换到 `输入参数` 选项卡：
     - `SenderIP`：保持默认 `127.0.0.1`（本地环回）；
     - `SenderPort`：填入刚才 Sender 监听的端口（例如 `5000`）；
     - `SenderLotMode`：选择手数模式（默认 `LOT_MULTIPLIER` 倍率模式）；
     - `SenderLotParam`：设置手数倍率（例如 `1.0` 为等比例跟随，`0.5` 为半手数跟随）；
   - 点击确定。
3. **完成！** 在主账户下单、修改止损或平仓，从账户将在 2 毫秒内同步执行。

## 3. 5分钟快速上手：中央枢纽模式 (Hub Mode)

适合管理分布在不同 VPS 上的多个主从账户，提供统一 Web 监控面板、手机推送与双机热备。

### 步骤 1：启动 Hub 服务端
1. 解压 `mt-copier-hub-suite-v1.0.0.zip`，进入 `Hub-Server` 文件夹；
2. **前台调试运行**：双击运行 `start_hub.bat`；
3. **生产后台守护运行（推荐）**：右键点击 `install_service.bat` -> 选择 **以管理员身份运行**，Hub 即被注册为原生 Windows 服务（开机自动静默启动，异常自动拉起）；
4. 打开浏览器访问：`http://127.0.0.1:6010`；
5. 首次登录会提示设置管理员密码，设置后进入全网交易大屏。

### 步骤 2：配置客户端连接 Hub
1. 客户端文件部署与直连模式完全一致；
2. **在主账户 (Sender)**：
   - `HubEndpoint` 填入 Hub 的地址，例如 `127.0.0.1:6000`（若跨 VPS 则填入 Hub 所在服务器的公网 IP/域名与端口，如 `123.45.67.89:6000`）；
3. **在从账户 (Receiver)**：
   - `HubEndpoint` 填入相同的 Hub 地址 `127.0.0.1:6000`；
   - `SenderIP` 和 `SenderPort` 无需填写；
4. 挂载后，刷新 Web 浏览器面板，在拓扑大屏上能立刻看到上线的节点卡片、实测网络延迟与实时持仓明细。

## 4. 发送端 (CopierSender) 参数逐项详解

`CopierSender` 挂载在主账户（信号源）图表上，负责捕获所有交易动作与持仓快照，对外广播。

### 1. 网络连接与模式 (Connectivity & Mode)
| 参数名 | 默认值 | 允许值 | 详细用途与设置指导 |
| :--- | :---: | :--- | :--- |
| **`HubEndpoint`** | *(空)* | 格式为 `IP:Port`，例如 `127.0.0.1:6000` | **中央 Hub 地址**。<br>• **留空**：运行在直连模式 (Direct Mode)，仅向本地/内网监听端口广播。<br>• **填入地址**：运行在 Hub 模式，主动连接中心服务器上报信号与仓位。 |
| **`BindAddress`** | `*` | `*` 或 具体本地 IP (如 `127.0.0.1`) | **本地网络绑定地址**。<br>• `*`：绑定本机所有可用网卡（`0.0.0.0`），推荐默认值。<br>• 指定 IP：多网卡或专有网络时限制绑定接口。 |
| **`EventsPort`** | *(空)* | 空 或 `1024 ~ 49151` 整数 | **直连模式监听端口**。<br>• **留空 (推荐)**：系统自动以 `5000 + (账号 % 1000)` 生成固定独立端口，彻底防止多账户端口冲突。<br>• **指定端口**：手动指定唯一端口（如 `5555`）。 |
| **`UseCurve`** | `false` | `true` / `false` | **ZeroMQ CURVE 256 位椭圆曲线高强度加密**。<br>内网或本机使用可设为 `false`；跨越不安全的公网且未使用 VPN/TLS 时建议设为 `true`。 |

### 2. 发送频率与性能 (Cadence & Performance)
| 参数名 | 默认值 | 允许值 | 详细用途与设置指导 |
| :--- | :---: | :--- | :--- |
| **`SnapshotSeconds`** | `15` | `0 ~ 3600` (秒) | **全量权威快照主动推送间隔**。<br>除了在开仓、平仓瞬时推送事件外，每隔 N 秒全量校验广播当前所有持仓。用于网络抖动后的自动对齐补单（0 为关闭定时快照，不推荐）。 |
| **`HeartbeatSeconds`** | `5` | `1 ~ 60` (秒) | **心跳包上报间隔**。<br>向接收端或 Hub 广播当前账户净值、余额、浮动盈亏与存活状态。 |
| **`PollMs`** | `5` | `1 ~ 100` (毫秒) | **底层事件轮询周期**。<br>5ms 轮询带来极佳的微秒级开仓捕获响应，同时 CPU 消耗微乎其微。 |

### 3. 订单过滤 (Filters)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`IncludeSymbols`** | *(空)* | **品种过滤白名单与黑名单**。<br>• **留空**：广播所有品种交易。<br>• **白名单**：输入逗号分隔的品种名，如 `EURUSD,GBPUSD,XAUUSD`，仅广播这些品种。<br>• **黑名单**：以 `!` 开头，如 `!BTCUSD,!ETHUSD`，排除加密货币，其余全部广播。 |
| **`IncludeMagicNumbers`** | *(空)* | **魔术数 (Magic Number) 过滤**。<br>• **留空**：跟主账户上的全部订单（包括手工单和所有 EA 单）。<br>• `0`：**仅跟主账户上的手工单**，忽略任何 EA 下的单。<br>• `1001,1002`：只跟特定魔术数的量化策略订单。 |

### 4. 手数广播提示 (Sizing Hint)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`FixedLotSize`** | `0.0` | **全局强制发单手数**。<br>若设置大于 0（例如 `0.1`），Sender 无论主账户实际开多少手，广播出去的报文都显示为该手数（0 表示按真实开仓手数广播）。 |
| **`LotSizeMultiplier`** | `0.0` | **源端手数乘数**。<br>在 `FixedLotSize=0` 时生效，对广播出的原始手数进行预乘（0 表示不修改）。 |

### 5. 系统与显示 (System & Display)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`LogLevel`** | `2` | 日志级别：`0`=仅错误，`1`=警告，`2`=常规信息 (Info，推荐)，`3`=深度调试 (Debug)。 |
| **`StatusEnabled`** | `true` | 是否记录并处理各从端回传的 ACK 回执与 STAT 报告。 |
| **`ShowPanel`** | `true` | 是否在图表上绘制状态面板（显示连接数、运行耗时、广播总数等）。 |

## 5. 接收端 (CopierReceiver) 参数逐项详解

`CopierReceiver` 挂载在从账户图表上，负责接收信号并根据本端的风控规则、手数策略精确执行交易。

### 1. 网络连接与模式 (Connectivity & Mode)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`HubEndpoint`** | *(空)* | **中央 Hub 接口地址**（例如 `127.0.0.1:6000`）。**留空即为 Direct 直连模式**。 |
| **`SenderIP`** | `127.0.0.1` | **直连模式下主账户 IP**。同机/同 VPS 填 `127.0.0.1`；局域网互跟填主账户局域网 IP。 |
| **`SenderPort`** | `5555` | **直连模式下主账户端口**。必须与主账户 Sender 提示的端口完全一致。 |
| **`UseCurve`** | `false` | 是否开启加密（必须与 Sender 端保持相同开关）。 |
| **`SenderServerKey`** | *(空)* | 当 `UseCurve=true` 时，填入 Sender 自动生成的 Z85 公钥。 |
| **`InpMagic`** | *(空)* | **接收端本地魔术数**。<br>留空时系统自动根据 `SenderPort` 或 Sender 标识生成唯一 Magic；也可手动指定（如 `888888`），系统据此区分手工单与跟单仓位。 |

### 2. 手数模式与品种映射 (Sizing & Symbol Mapping)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`SenderLotMode`** | `LOT_MULTIPLIER` | **核心手数计算模式**（详见后文实操章节）：<br>• `LOT_MULTIPLIER` (0)：倍率跟随（从端手数 = 主端手数 × `SenderLotParam`）；<br>• `LOT_FIXED` (1)：固定手数（每次开仓恒为 `SenderLotParam` 手）；<br>• `LOT_OFF` (2)：1:1 直通主端手数不经 LotParam 缩放（如需仅观察不发单，请设置 `InpIgnoreNewEntrySignals=true`）；<br>• `LOT_EQUITY_RATIO` (3)：净值比例跟随。 |
| **`SenderLotParam`** | `1.0` | **手数参数值**。配合上方模式使用。在倍率模式下 `1.0` 代表 1:1 等比例跟随；在固定手数模式下 `0.05` 代表每次开 0.05 手。 |
| **`SenderSuffix`** | *(空)* | **从端券商品种后缀**。如主端为 `EURUSD`，本端券商为 `EURUSD.pro`，此处填 `pro`（系统会自动拼装，支持自动识别前置点号）。 |
| **`SenderSymbolMap`** | *(空)* | **完全自定义品种映射对**。逗号分隔 `源=目标`。<br>例如黄金跨券商：`GOLD=XAUUSD,XAUUSD.m=XAUUSD`。 |

### 3. 风控熔断门禁 (Risk Limits)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`InpMaxLotsPerPosition`** | `0.0` | **单笔最大手数限制**。例如设为 `2.0`，无论按比例算出来是 5 手还是 10 手，本地单笔开仓绝对不会超过 2.0 手（0 为不限制）。 |
| **`InpMaxTotalLots`** | `0.0` | **跟单总持仓手数上限**。本端所有跟单持仓手数总和达到此阈值时，自动拦截后续所有新开仓（0 为不限制）。 |
| **`InpMaxOpenPositions`** | `0` | **跟单最大开仓单数上限**。例如设为 `10`，持仓达 10 笔后不再开新单（0 为不限制）。 |
| **`InpDailyLossPct`** | `0.0` | **每日净值亏损熔断比例 (%)**。以当天 0 点净值为基准，若当日亏损达到如 `5.0` (即 5%)，触发熔断，当天停止接收新单。 |
| **`InpMaxDrawdownPct`** | `0.0` | **历史最大动态回撤熔断比例 (%)**。达到后彻底停机保护（0 为不启用）。 |
| **`InpRiskCloseAllOnTrip`** | `false` | **触发风控熔断时是否强平所有已持仓订单**。<br>• `false`：仅停止开新单，老订单仍按止损或信号自然平仓。<br>• `true`：触发熔断时瞬间市价全平当前所有跟单持仓（紧急避险）。 |

### 4. 订单执行与止盈止损 (Execution & Stops)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`InpDeviationPoints`** | `30` | **最大允许滑点 (Points)**。市场剧烈波动时，若滑点超过 30 点（3 个基准点）则拒绝入场，防止恶性滑点。 |
| **`InpEmergencySLPips`** | `0.0` | **本地应急止损点数 (Pips)**。开仓瞬间立即强制挂上的硬性止损距离（0 为不挂），防范网络闪断。 |
| **`InpEmergencyTPPips`** | `0.0` | **本地应急止盈点数 (Pips)**。开仓瞬间立即强制挂上的硬性止盈距离（0 为不挂）。 |
| **`InpMirrorStops`** | `true` | **是否镜像主账户的止损/止盈**（推荐 `true`）。采用点数相对幅度重锚，消除两端入场价差带来的误触发。 |
| **`InpInvertTrades`** | `false` | **反向跟单开关**。设为 `true` 时，主端 Buy 则从端 Sell，主端 Sell 则从端 Buy，止盈止损自动对调。 |
| **`InpReopenClosedMirrors`**| `false` | 从端手动平仓后，若主端仍持仓是否重新开仓。<br>**强烈保持 `false`**，保护交易员的手动干预意图不被系统覆盖。 |
| **`InpDedupDuplicates`** | `true` | **重复订单防护**。防止因极端网络重发导致同一 UID 开出两笔相同订单（推荐 `true`）。 |
| **`InpStopsThrottleSeconds`**| `2` | **止损同步流控最小间隔 (秒)**。追踪止损频繁微调时，限速每 2 秒最多向券商提交一次改单，防止券商报 `10027` 封禁 API。 |
| **`InpMarketOpenDelayMinutes`**| `5` | **周一开盘点差保护缓冲期 (分钟)**。周一刚开市的前 5 分钟点差极度畸形，期间不接收新开仓。 |
| **`InpMaxSpreadMultiplier`**| `2.5` | **异常点差倍数过滤**。当前实时点差超过该品种平时平均点差 2.5 倍时暂停开仓。 |

### 5. 过滤与方向规则 (Filters & Direction)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`InpPermittedSymbols`** | *(空)* | 本地允许跟单的品种名单（支持 `!` 排除）。 |
| **`InpPermittedMagic`** | *(空)* | 本地允许跟单的主端 Magic 列表。 |
| **`InpMinSenderLotSize`** | `0.0` | 主端手数过小则忽略（例如主端打架试盘的 0.01 手不跟）。 |
| **`InpMaxSenderLotSize`** | `0.0` | 主端手数过大则忽略。 |
| **`InpIgnoreUids`** | *(空)* | 针对特定 8 位 UID 的黑名单。 |
| **`InpNoBuy`** | `false` | 设为 `true` 则完全单向屏蔽所有 Buy 做多开仓。 |
| **`InpNoSell`** | `false` | 设为 `true` 则完全单向屏蔽所有 Sell 做空开仓。 |
| **`InpIgnoreNewEntrySignals`**| `false` | **只平不开开关**。设为 `true` 后只跟随平仓信号，不再开新单（常用于策略平稳撤退）。 |
| **`InpIgnoreAllExitSignals`** | `false` | 忽略主端的平仓信号（从端开仓后完全由自己手动管理或硬止损出场）。 |

### 6. 防堆叠与挂单延时 (Anti-Stack & Delays)
| 参数名 | 默认值 | 详细用途与设置指导 |
| :--- | :---: | :--- |
| **`InpCheckForExistingPosition`**| `EXIST_OFF` | **防过度堆叠加仓**：<br>• `EXIST_OFF` (0)：不限制加仓；<br>• `EXIST_SYMBOL` (1)：该品种已有持仓时不再开新单；<br>• `EXIST_DIRECTION` (2)：该品种已有同向持仓时不加仓。 |
| **`InpWaitForSeconds`** | `0` | 主端开仓后，延迟 N 秒再在本地执行（防快枪滑点）。 |
| **`InpWaitForProfitPips`** | `0.0` | **回调确认开仓**：正数代表主端盈利 N 点后再追入；负数代表主端回调被套 N 点后再入场接飞刀。 |
| **`InpPendingFillGraceSeconds`**| `1.5` | 挂单超时成交容忍宽限期 (秒)。 |

### 7. 交易时段控制 (Schedule & Timeout)
| 参数名 | 默认值 | 详细用途与设置指导 |

## 6. 手数模式与资金风控实操配置指南

### 场景 1：等比例跟随（主账户与从账户资金相当）
- `SenderLotMode` = `LOT_MULTIPLIER` (0)
- `SenderLotParam` = `1.0`
- *效果*：主账户开 0.5 手，从账户精确开 0.5 手。

### 场景 2：按固定比例缩放（主账户 $10,000，从账户 $2,000）
- `SenderLotMode` = `LOT_MULTIPLIER` (0)
- `SenderLotParam` = `0.2`
- *效果*：主账户开 1.0 手，从账户按 1/5 比例开 0.2 手。

### 场景 3：固定手数防守（无论主账户开多大，从账户恒定小手数）
- `SenderLotMode` = `LOT_FIXED` (1)
- `SenderLotParam` = `0.05`
- *效果*：主账户开 0.01 或 10 手，从账户每笔恒定执行 0.05 手。

### 场景 4：按动态净值比例自动匹配 (Equity Ratio)
- `SenderLotMode` = `LOT_EQUITY_RATIO` (3)
- `SenderLotParam` = `1.0`
- *效果*：系统每秒实时读取双方真实净值，自动换算：
  $$\text{从端手数} = \text{主端手数} \times \left( \frac{\text{从端净值}}{\text{主端净值}} \right) \times \text{SenderLotParam}$$
  当从端资金不断增厚或出金时，手数全自动无级缩放。

## 7. 跨券商品种名称与后缀映射方案

在真实跟单中，不同经纪商针对同一品种的命名往往存在差异（如带后缀或代码完全不同）：

### 常见情况 A：目标券商全品种带统一后缀 (如 `.pro` 或 `m`)
- 主端券商：`EURUSD`, `GBPUSD`, `XAUUSD`
- 从端券商：`EURUSD.pro`, `GBPUSD.pro`, `XAUUSD.pro`
- **配置方法**：在 `CopierReceiver` 中设置：
  ```ini
  SenderSuffix = pro
  ```
  *(系统会自动适配点号，填 `pro` 或 `.pro` 均可)*。

### 常见情况 B：黄金或特定品种代码差异
- 主端券商黄金叫 `GOLD`，从端券商黄金叫 `XAUUSD`；
- 主端原油叫 `USOIL`，从端原油叫 `WTI`；
- **配置方法**：在 `CopierReceiver` 中设置 `SenderSymbolMap`：
  ```ini
  SenderSymbolMap = GOLD=XAUUSD,USOIL=WTI
  ```

## 8. 反向跟单 (Reverse Copying) 配置规范

反向跟单主要用于对抗爆仓策略、负期望网格策略或进行多账户反向对冲。

### 核心设置：
在从端 `CopierReceiver` 参数中设置：
- `InpInvertTrades` = `true`

### 系统的自动化保障机制：
1. **订单方向自动翻转**：
   - 主端 Buy ➔ 从端自动下 Sell；
   - 主端 Sell ➔ 从端自动下 Buy。
2. **止损与止盈角色智能翻转**：
   - 主端的止盈（Take-Profit）在从端自动变成止损（Stop-Loss）；
   - 主端的止损（Stop-Loss）在从端自动变成止盈（Take-Profit）；
   - 系统内部自动基于相对点数幅度（Magnitude）重新计算价格，**彻底杜绝价格逆序导致的券商 `10016` 无效价格拒单**。

## 10. 高频排错与常见问题清单 (FAQ)

### Q1: 图表左上角 EA 名字旁是哭脸 🙁 或灰帽子，无法通单？
- **原因**：MetaTrader 安全策略禁止了 DLL 导入或禁止了自动交易。
- **解决**：
  1. 按 `F7` 检查当前 EA 属性 -> 勾选 `允许算法交易` 与 `允许 DLL 导入`；
  2. 检查 MT4/MT5 顶部总开关【自动交易 / Algo Trading】按钮是否为绿色启动状态。

### Q2: 提示 `ZeroMQ error: cannot load library libzmq.dll` 或错误代码 4111？
- **原因**：缺少 `libzmq.dll` 或放错了文件夹。
- **解决**：
  - MT4（32 位）必须放入 `MQL4\Libraries\libzmq.dll`；
  - MT5（64 位）必须放入 `MQL5\Libraries\libzmq.dll`；
  - 注意：两者的 DLL 架构不同（32位 vs 64位），不可混淆使用。

### Q3: Direct 模式下从端状态栏显示 `Connecting...` 迟迟不连接？
- **排查步骤**：
  1. 确认 Sender 所在图表正常加载且显示 `Listening on port: 5000`；
  2. 检查 Receiver 端的 `SenderPort` 是否与该端口一致；
  3. 若跨不同电脑直连，请确保 Sender 所在系统的 Windows 防火墙已放行该端口（或改用更为推荐的 Hub 模式）。

### Q4: 订单开出来了，但主账户平仓后从账户没有跟着平仓？
- **排查步骤**：
  1. 检查 Receiver 是否开启了 `InpIgnoreAllExitSignals`（忽略平仓信号）；
  2. 检查该订单是否由交易员在从端本地手动部分平仓过；系统为防反复重开，会开启意图保护环；
  3. 检查 Receiver 日志栏是否报告券商市场停盘或点差过大触发保护。

### Q5: 为什么主从账户入场价有轻微差价，但止损点数完全一致？
- **原理**：系统默认采用**相对幅度重锚算法 (Relative Distance Re-anchoring)**，而非照抄主端绝对价格。如果两家券商存在 1 个点的报价基准偏差，照抄绝对价格会导致提前扫损；按相对点数重锚能确保从账户与主账户承受完全等量的风险点数。
